# Plauder fork maintenance

This repository is a fork of [`cinnyapp/cinny`](https://github.com/cinnyapp/cinny).
It tracks upstream's `dev` branch and keeps Plauder-specific changes on `plauder`.

## Branches

- **`dev`** is a read-only mirror of `cinnyapp/cinny:dev`. The sync workflow
  fast-forwards it; never commit to it.
- **`plauder`** is the default/integration branch. It contains upstream `dev`
  plus the Plauder theme, branding, and call changes.
- **`sync/dev-<sha>`** branches are transient and generated by the workflow.
  Auto-merged branches are deleted automatically.

Upstream releases/tags are not tracked. Tag a known-good `plauder` commit if a
stable point is needed.

## Automatic sync

[`.github/workflows/sync-upstream.yml`](.github/workflows/sync-upstream.yml)
runs daily and can be started manually. It calls
[`.github/scripts/sync-upstream.sh`](.github/scripts/sync-upstream.sh), which:

1. Fetches only `cinnyapp/cinny:dev`, with full history.
2. Fast-forwards fork `dev`. If `dev` has diverged, it stops instead of
   overwriting it.
3. Exits if `plauder` already contains the upstream commit.
4. Leaves an existing open `sync/*` PR untouched (preserving manual conflict
   fixes) and tries to enable auto-merge.
5. Creates `sync/dev-<sha>` from `plauder`, merges `dev`, and opens a PR.
6. Enables auto-merge when the PR is conflict-free and `Plauder build` passes.

Manual runs always sync the latest `dev`; the only input is `auto_merge`, which
can be set to `false` to skip auto-merge.

## Conflicts

Only paths in `ALLOW_OURS` in the sync script may be auto-resolved. It currently
contains only the intentionally deleted `prod-deploy.yml`.

Everything else is treated as a real conflict. The workflow then opens a
**draft PR** and comments with resolution steps:

```sh
git fetch origin
git checkout sync/dev-<sha>
git merge origin/plauder
# resolve conflicts
npm ci && npm run build
git push origin sync/dev-<sha>
```

Or use GitHub's **Resolve conflicts** button. Mark the PR ready for review when
it is clean and `Plauder build` is green; the next scheduled run enables
auto-merge.

Only add a path to `ALLOW_OURS` after confirming that upstream changes to it are
not needed. Never add dependency, auth, SDK, or call files. After the first dev
migration, `About.tsx` and `WelcomePage.tsx` may become safe if their only
recurring conflict is a version line; verify with a dry-run merge first.

## Holding a sync PR

Convert the PR to **draft** to prevent auto-merge. Draft PRs are never merged by
the workflow. Mark it ready for review to resume.

## Required repository settings

One-time setup on `plauderparty/cinny`:

1. **Actions enabled** (Settings → Actions → General).
2. **Default branch: `plauder`** (Settings → General). Scheduled workflows only
   run from the default branch.
3. **Allow auto-merge** (Settings → General).
4. **Allow merge commits** (Settings → General → Pull requests). The workflow
   uses merge commits, never squash or rebase, to preserve upstream ancestry.
5. A **ruleset/branch protection** for `plauder`:
   - require a pull request before merging;
   - require the **`Plauder build`** status check;
   - no required approvals (the bot cannot approve its own PR).
6. A fine-grained personal access token stored as the **`SYNC_TOKEN`** Actions
   secret with these repository permissions:
   - Contents: read/write
   - Pull requests: read/write
   - Workflows: read/write

`GITHUB_TOKEN` cannot drive the full flow: PRs created with it do not trigger
`pull_request` workflows, so `Plauder build` would never run. The workflow falls
back to `GITHUB_TOKEN` but disables auto-merge and warns.

`dev` must not be protected in a way that blocks the fast-forward push. Only
`plauder` needs the PR ruleset.

### Bootstrap order

The `Plauder build` check only appears in GitHub's required-check picker after it
has run once.

1. Push the workflow files to `plauder`.
2. Enable Actions, set the default branch to `plauder`, enable auto-merge, and add
   `SYNC_TOKEN`.
3. Run the sync workflow manually (or open any small PR to `plauder`) so
   `Plauder build` runs once.
4. Add `Plauder build` as the required status check on `plauder`.
5. Resolve the first `dev` migration PR, verify `Plauder build`, and merge it.

Do not enable auto-merge before the required check exists, or GitHub may merge
the PR immediately.

## Build check

[`.github/workflows/plauder-ci.yml`](.github/workflows/plauder-ci.yml) runs
`npm ci` and `npm run build` on PRs targeting `plauder`. The job is named
**`Plauder build`** and is the required check.

`npm run typecheck` is not a gate: upstream's TypeScript setup is not type-clean,
and upstream CI only runs the Vite build.

## First dev sync is a migration

The fork was based on upstream `v4.12.6`, while upstream `dev` has since replaced
`matrix-js-sdk` with `neurone`, moved auth components, and changed several hooks.
The first sync therefore has many conflicts and must be ported manually. After
that merge lands, future `dev` syncs are incremental.

The first run opens a draft PR with the sync branch pointing at upstream `dev`.
Merge `origin/plauder` into that branch, resolve conflicts, build, push, and mark
it ready.

## Removing stale branches

The fork should normally contain only `dev` and `plauder` (plus transient
`sync/*` branches). To remove every other branch:

```sh
git fetch origin --prune

# dry run
git for-each-ref --format='%(refname:strip=3)' refs/remotes/origin \
  | grep -vxE 'dev|plauder|HEAD'

# delete
git for-each-ref --format='%(refname:strip=3)' refs/remotes/origin \
  | grep -vxE 'dev|plauder|HEAD' \
  | while IFS= read -r branch; do
      git push origin --delete "$branch"
    done
```

Add branches you want to keep to the `grep -vxE` pattern. Deleting a branch
closes its open PR. This affects only the fork, not `cinnyapp/cinny`.

To delete a single closed sync branch:

```sh
git push origin --delete sync/dev-<sha>
```

## Troubleshooting

- **Workflow did not run on schedule:** Actions must be enabled and the workflow
  must exist on the default branch (`plauder`). Schedules pause after 60 days of
  repository inactivity; run the workflow manually to restart.
- **`dev` fast-forward failed:** `dev` has commits not in upstream. Reconcile it
  manually; the workflow refuses to force-push it.
- **PR has no `Plauder build` check:** `SYNC_TOKEN` is missing or lacks
  pull-request/workflow permissions, or the PR is a conflicted draft.
- **Auto-merge not enabled:** check “Allow auto-merge”, the `Plauder build`
  required check, and whether the PR is a draft. Auto-merge cannot resolve
  conflicts.
- **Build fails after a sync:** fix the branch, push, and let the check re-run.
